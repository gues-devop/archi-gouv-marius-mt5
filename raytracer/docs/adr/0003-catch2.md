# 0003 — Use Catch2 for Unit Testing

## Context

The course follows a TDD workflow, so the testing framework should be easy to read and write for participants new to C++ testing. Raytracing uses floating-point arithmetic, so tests need approximate comparisons.

Alternatives considered:

- **GoogleTest** — widely used, but its setup and assertion macros can be more verbose for teaching.
- **doctest** — offers a similar style and lighter compile times, but has a smaller ecosystem.
- **Boost.Test** — mature, but would add Boost as a dependency.

## Decision

Use Catch2 v3.8.1, fetched with CMake `FetchContent`. Write tests with `TEST_CASE` and `REQUIRE` / `CHECK`; use Catch2's approximate comparisons for floating-point values. Register the cases with CTest using `catch_discover_tests`.

## Status

Proposed

## Consequences

**Positive:**

- Descriptive `TEST_CASE` names and `REQUIRE` / `CHECK` assertions are readable for teaching and live coding.
- Catch2 provides approximate comparisons for floating-point values.
- Linking `Catch2::Catch2WithMain` avoids writing a separate test `main()`.

**Negative:**

- Catch2 v3 is a compiled library, so it takes longer to build than the single-header v2.
- Catch2 is less commonly used in production C++ codebases than GoogleTest.
- The version is pinned in `CMakeLists.txt`; updating it requires changing that file.
